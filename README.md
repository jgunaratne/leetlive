# LeetLive

Practice coding interviews by voice. A live AI interviewer runs a phased mock interview while you code, a tutor mode explains concepts, and each session ends with a written hiring-committee scorecard.

## How it works

```
Browser (editor + mic, AudioWorklet PCM) ──WS──► Node proxy ──► Gemini Live (voice interviewer / tutor)
        │                                           │
        └── REST ──► /api/solve      reference solution + complexity (structured JSON)
                     /api/visualize  self-contained HTML step-through of the algorithm
                     /api/chat       tutor chat sidebar (Gemini or a local LM Studio model)
                     /api/decision   hiring decision from code + transcript + metrics
                                           │
                                     SQLite (sessions, transcripts)
```

- **Interviewer:** a voice agent that tracks five interview phases (clarify → approach → code → test → follow-up). It gives hints that point at what the problem is asking without giving the answer.
- **Tutor mode:** a separate persona that teaches step by step and waits for you at each stage. It can run on a local model through LM Studio.
- **Turn-taking:** silence threshold, end-of-turn sensitivity and prefix padding are configurable, so you can think aloud without being cut off.
- **Scorecard:** the code, transcript and timing metrics are combined into a structured hire/no-hire write-up.

## Practice formats

Open **Practice formats** from the header (or `/practice.html`) for six interview formats beyond LeetCode-style problems. The original Solve / Interviewer / Professor / Decision flow is unchanged.

| Format | What you practise | How it works |
| --- | --- | --- |
| **Levels** | A timed, multi-level take-home (about 90 min) | One system grows across 4 levels. A level unlocks only when its visible **and hidden** tests pass, and every run re-checks all earlier levels — a broken earlier level shows as a regression. |
| **Concurrency** | Crawler / job-runner style problems | Same level mechanics. Helper code simulates a slow dependency, so tests can check a concurrent version is actually faster and stays within an in-flight limit. The interviewer pushes twists once your first version works. |
| **Debugging** | Finding planted bugs in an unfamiliar module | Starts with buggy code and failing tests; hidden tests catch the rest. The interviewer asks for hypotheses, never names the bug. |
| **System Design** | A semi-guided design round (about 50 min) | The interviewer holds a question plan, asks focused 5–15 minute questions, moves you between them, injects a twist mid-way, and leaves time for your questions. Your notes are shared with it. |
| **Design Review** | Critiquing someone else's design | A realistic design doc with planted flaws. You review, rank and propose fixes; the scorecard compares what you found against the planted list. |
| **Screen** | A recruiter call | Paste a job description. The recruiter pushes "why this company" two or three layers deep, checks your fit line by line, and asks for your pitch. |

Every format ends with **End & score**: a scorecard with a decision, 1–4 ratings per dimension with evidence, and what to practise next. Attempts and scorecards are kept under **History**.

### Generated problems are verified

Problems are generated by Gemini, then checked before you see them: the hidden reference solution is run against every test, and any test it fails is dropped (and the generator gets one retry with the failures). A debugging problem is rejected if its buggy code passes everything. The parts you shouldn't see — hidden tests, the reference, planted bugs and flaws, the interviewer's question plan — never reach the browser; the voice interviewer receives them server-side as a private brief.

### The code runner

Python and JavaScript are supported. Each test is a short snippet that passes if it runs without raising (`assert …` in Python; `assert.equal(…)` from `node:assert/strict` in JavaScript, inside an async function so tests can `await`). Each test runs against a fresh load of your code, with a per-test timeout.

By default code runs in a local subprocess with a minimal environment. Set `RUNNER_SANDBOX=docker` to run each test batch in a throwaway container with no network and capped memory/CPU (see `.env.example`). Use Docker if the app is reachable by anyone but you, or if you import problems you haven't read.

### Bring your own problem

**Import JSON…** accepts a problem in the generator's shape, for example one you've written up from a question bank. Coding problems need a `reference` solution so their tests can be verified.

```json
{
  "format": "levels",
  "language": "python",
  "payload": {
    "title": "In-memory bank",
    "summary": "Accounts, transfers, ranking and scheduled payments.",
    "setup": "",
    "starter": "class Bank:\n    def deposit(self, timestamp, account_id, amount):\n        raise NotImplementedError",
    "reference": "class Bank:\n    ...",
    "interviewerNotes": ["How would you add an audit log?"],
    "levels": [
      {
        "title": "Accounts and deposits",
        "spec": "- `deposit(timestamp, account_id, amount) -> int | None` …",
        "tests": [
          { "name": "deposit to new account", "code": "b = Bank()\nassert b.deposit(1, 'a', 5) == 5", "hidden": false },
          { "name": "missing account", "code": "assert Bank().withdraw(1, 'x', 5) is None", "hidden": true }
        ]
      }
    ]
  }
}
```

Other formats use the same envelope: **debugging** takes `context`, `buggy`, `reference`, `bugs[]` and `tests[]`; **system-design** takes `prompt`, `questions[{question, strongAnswer}]` and `twists[]`; **design-review** takes `doc` and `flaws[{title, severity, location, explanation}]`.

Practice data lives in `data/practice.db`, separate from your existing session history in `data/leetlive.db`.

## Stack

Node.js · Express · WebSockets · Gemini Live API (`@google/genai`) · better-sqlite3 · vanilla JS frontend

## Run it

```bash
npm install
cp .env.example .env      # set GEMINI_API_KEY, or GOOGLE_CLOUD_PROJECT for Vertex AI
npm start                 # http://localhost:3000
```

For microphone access on any host other than `localhost`, put `cert.pem` and `key.pem` in `certs/` to serve over HTTPS (see `src/config.js`).
